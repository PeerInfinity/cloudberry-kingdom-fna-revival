# Cloudberry Kingdom on the R36S (ArkOS) — Build & Install

A PortMaster-style port: **Mono + classic SDL2 FNA + OpenGL ES**, running **full speed** on the
Anbernic R36S. Read [`TECHNICAL.md §7–8`](TECHNICAL.md#7-the-r36s-handheld-port) first for the *why*;
this is the *how*.

## What you must supply (the runtime)

This repo does **not** ship the FNA/Mono runtime binaries — they belong to the FNA/PortMaster
ecosystem, not to us. The easiest source is an existing **PortMaster FNA-on-Mono port**, e.g.
**Dust: An Elysian Tail**. From such a port, copy these into `build/r36s-base/`:

```
build/r36s-base/
  libs/        libFNA3D.so.0  libFAudio.so.0  libtheorafile.so  hacksdl.so  libastcUtil.so
  dlls/        FNA.dll  FNA.dll.config  SDL2-CS.dll  SDL2-CS.dll.config  (OpenAL-CS.dll …)
  tools/       hacksdl.conf  asoundrc
  MMLoader.exe
  gamecontrollerdb.txt
```

- `dlls/FNA.dll` is the **classic, SDL2-based** FNA that `Game.Mono.csproj` compiles against — using
  the exact runtime you'll ship guarantees ABI compatibility.
- Mono itself is provided on-device by **PortMaster** (`mono-6.12.0.122-aarch64.squashfs`), mounted
  by the launcher.

## Build

```powershell
# 1. Apply patches + Game.Mono.csproj (once)
pwsh scripts/apply_patches.ps1 -GameRepo ..\Cloudberry-Kingdom

# 2. Full content first (needed as a base), then the resized R36S set
pwsh build/build_content.ps1
pwsh build/build_content_r36s.ps1        # textures -> 40%, drops videos -> BuiltContent-R36S

# 3. Assemble the PortMaster port
pwsh build/build_r36s_port.ps1           # -> dist/CloudberryKingdom-Port
```

`build_r36s_port.ps1` compiles `Game.Mono.csproj` (net472), then assembles:

```
dist/CloudberryKingdom-Port/
  Cloudberry Kingdom.sh            <- PortMaster launcher (LF line endings!)
  cloudberry/
    MMLoader.exe  port.json
    libs/ dlls/ tools/             <- the runtime you supplied
    gamedata/
      CloudberryKingdom.exe        <- our Mono build
      Content/                     <- resized xnb + shaders + music + data (no videos)
      gamecontrollerdb.txt
```

## Install

No Wi-Fi/SSH needed. Put the SD card in your PC and copy **both** items into the device's ports
folder (same place your other PortMaster ports live, e.g. `/roms/ports/`):

- `Cloudberry Kingdom.sh`
- `cloudberry/`

Launch **Cloudberry Kingdom** from the **Ports** menu. A `cloudberry/log.txt` is written on each run
(handy for debugging: it prints the FNA3D driver, GL renderer, MojoShader profile).

## What the launcher sets (and why)

| Env var | Reason |
|---|---|
| `FNA3D_FORCE_DRIVER=OpenGL` | Mali-G31 has no usable Vulkan on Linux |
| `FNA3D_OPENGL_FORCE_ES3=1` | force a GLES 3 context |
| `FNA3D_OPENGL_FORCE_VBO_DISCARD=1` | Mali buffer-orphaning perf hack |
| `MONO_IOMAP=all` | XNA uses Windows-style `Content\...` paths; map them case/`\`-insensitively |
| `SDL_VIDEODRIVER=kmsdrm` | render straight to the display (no X) |
| `HACKSDL_CONFIG_FILE=...` | 640×480 low-res screen shim (reports 960×720, sets a 640×480 window) |

## Performance: the "Anders" mode

The handheld build **defaults to Anders scenery** (simpler tilesets = full speed) — this, not
resolution or texture size, is what makes it fast (see
[`TECHNICAL.md §8`](TECHNICAL.md#8-the-performance-story-read-this)). You can still toggle it off in
**Options** if you want the varied art back (and accept the slowdown).

## Controls

Native gamepad support via SDL + `gamecontrollerdb.txt`. Exit with the PortMaster hotkey
(**Start + Select**), like other ports.

## Aspect ratio

The game is 16:9; the R36S screen is 4:3, so you'll see small letterbox bars. Forcing 4:3 fullscreen
was tried and **rejected** — it stretches/distorts the 16:9 art and (rendering more pixels) is
slower. Correct 16:9 with bars is the shipped default.
